# Warehouse Yard — squad tactics prototype

Combat demo for Bryan's next game after Ashvale: modern squad tactics (Full Spectrum Warrior squad control + Aliens: Dark Descent look and campaign feel) with base building and async PvP planned later. This demo only tests the battle layer.

## The game idea (long term)
- Main HQ: level up, research weapons, build defenses, store vehicles, collect resources. Modern setting, human vs human.
- Missions: overlay of enemy territory, scouting options, pick the first target, take it, then push to the next outpost/checkpoint. Captured areas become sub-bases (recruit locals, repair gear, heal the wounded, build makeshift tech). Clear the region, upgrade HQ, continue the war.
- Later: async online raids. Players build base defenses, and their forces defend on their own when attacked.
- Visual target: close to Aliens: Dark Descent.

## The demo (warehouse-yard.html)
`warehouse-yard.html` is the page shell (markup only). Three.js r128 from cdnjs (global `THREE`) renders the 3D world; a 2D canvas overlay on top draws the HUD bits (hp bars, hit %, previews, tracers, rain). No build step: open the HTML directly or serve the folder statically.

### Code layout
Styles in `css/style.css`. Game code in `js/` as plain `<script>` files (not ES modules, so it still runs from `file://`). They share one global scope, so load order matters and is set in the HTML:
1. `core.js` constants (map size, colours), DOM handles, `hyp`/`clamp`/`rng`, `teamCol`
2. `map.js` map objects (`objs`), lamp/post data, LOS, cover, free-space queries
3. `pathfinding.js` nav grid, A* + string-pulling, cover points
4. `scene.js` `initGL()` (renderer, scene, camera), camera maths (`toS`/`toW`), textures, world meshes, lights, soldier models, `render()`
5. `state.js` battle state variables, `mk`, `reset`, `timeScale`
6. `combat.js` hit chance, shots, suppression, grenades, move assignment, enemy and squad AI, `update(dt)`
7. `waves.js` the opening dinghy landing (`startLanding` from the Deploy/again buttons, `landTick` via `waveTick`), the warehouse fight's phases, countdown and on-foot counterattack over the bridge, the wave-two assault AI (`waveTick` from `update`, `waveHud` every frame, `resetWaves` from `reset`)
8. `hq.js` temporary HQ points at captured objectives (medical/supply boxes, `HQ_ZONES`, `addZones`), the warehouse's popup and tour, camera pans (`startHQ`, `hqTick` via `waveTick`, `drawHQ` from the overlay, `panTick` every frame)
9. `mission.js` objectives 2–5 after the warehouse: per-objective defenders, completion, demolition charges, the enemy RPG and rockets, chain-exploding fuel tanks, the server core, the drawbridge and its panel, the objective tracker (`startObjective`, `missionTick` via `hqTick`, `missionFx` every tick, `drawMission` from the overlay, `resetMission` from `resetWaves`)
10. `vehicle.js` the jeep as a squad vehicle; dormant for now (Bryan took the vehicle out; nothing spawns a jeep, `jeepOf()` is null, its hooks do nothing)
11. `overlay.js` 2D overlay drawing and rain
12. `input.js` pointer/pinch/wheel handling (`bindInput`), `tap`
13. `hud.js` banner, status chip, buttons, keyboard (`bindHud`), detection ring, end screen
14. `cards.js` team tabs' health pips and the unit cards (portrait, name, status, heart monitor, equipment): `buildCards`, `updateCards` (from `hud()`), `drawCards` (every frame)
15. `progress.js` XP, levels, ranks, saving progress in localStorage, the after-action report (`showAAR`)
16. `save.js` saving the campaign at milestones and restoring it: Continue / Retry from last save / New game (`saveGame`, `continueGame`, `refreshSaveButtons`)
17. `audio.js` sound: recorded CC0 samples in `sounds/` (credits in `sounds/CREDITS.md`) for gunfire, explosions and the RPG launch; synthesised engines (combustion-pulse loops), rain, thunder, gate crash, explosion rumble; an outdoor echo; no UI beeps; mute button (`bindAudio` at boot, `audioFrame` every frame, `sfxShot`/`sfxCrash`/… from the game code)
18. `voice.js` squad radio voices: per-soldier lines (`VOICE_LINES`, sheet in `docs/voice-lines.md`), recorded files from `sounds/voice/` through a radio filter, browser speech as a stand-in (`say(u,key)`, `bindVoice` at boot; `callout()` speaks matching callouts)
19. `main.js` resize, frame loop, boot (shows the no-WebGL message and stops if `initGL()` fails)

Only `main.js` does work at load time beyond building pure data (map, nav grid, cover points); everything touching THREE or wiring events runs from boot.

### Decisions made (keep unless Bryan changes them)
- Real-time with slow-mo (quarter speed) while giving orders, plus Pause. Not turn-based.
- Squad is the main unit, split into two 2-man fire teams. Individuals are for special moves (flank, grenade, revive).
- Group move = two taps: first tap previews ghost positions (green = in cover, red = exposed, from known enemies), tap the marker again to go. Single soldier moves on one tap.
- Where soldiers stand (`makeAssign`, reworked after Bryan's complaints about far-off cover and runners): spots within 14 of the tap for one soldier, 32 for two, 45 for three or four, and in line of sight of the tap (same side of a wall). Candidates are cover points plus open slots in a line across the threat direction (back row penalised). The whole group's arrangement is chosen together: cover (×2) + sees enemy (0.3) − distance from tap/12 − walk/150 − spread beyond 30. Tapping a wall/container/crate/sandbag in the 3D view targets the spot just in front of the face you tapped (`tapTarget` in scene.js, using `objHeight` from map.js), not the ground hidden behind it.
- Drawn routes for independent soldiers (Bryan, inspired by mobile squad games): drag from a soldier to draw his route. He follows the line's shape; stretches through objects are routed round (`routeFromTrail` in combat.js, dropping a dead-end bit of line if that saves 15%+ locally); the end settles on cover within 18. Quarter speed while drawing, works while paused, map edge-scrolls while drawing.
- Sneak/run toggle (Bryan's design): button bottom right (`#gaitBtn`, `toggleGait`) shows the selected soldiers' gait (AUTO SNEAK / AUTO RUN). Pressing flips them to the other gait (amber, MANUAL), pressing again returns to auto. A soldier goes back to auto when he's selected again after not being selected (`select()` in input.js; always change the selection through it). Key R.
- Weapons tight while undetected: before contact the squad only fires at a hostile you tapped (or via Suppress/grenade). Striking first is an ambush: enemies need 1.4–2 s to react and the squad gets +0.15 hit chance for 1.5 s (`alertAll(msg,true)`, `ambushing()`). The hit pill shows "· ambush" while undetected. After contact, everyone fires freely.
- Soldiers act on their own to survive: return fire, shift to cover within 50 if exposed ~2 s, but never wander off on a plan of their own. Player orders lock out auto-moves for 4 s.
- Angled 3D camera, from the south by default (pitch 60° zoomed out → 46° zoomed in), rotatable by twisting. Bryan liked this far more than top-down. Screen-relative things (edge-scroll, labels placed below a point via `below()`) must account for `yaw`.
- Hit chance shown per shot as "64% · open / cover / heavy", XCOM style: best of the selected soldiers on that enemy; adds "· peek" if the shot needs a lean and "· ambush" while undetected; green ≥60 %, amber ≥35 %, red below; grey "no line" if nobody selected can shoot him.

### Controls
- Fit map button is top right of the map; the sneak/run toggle is bottom right (lifted above the cards when they show).
- Bottom bar: team tabs Alpha / Bravo / All (each with a health pip per soldier), Suppress, Clear. Tap a tab to select that team; tap it again while that group is selected to deselect it (Bryan).
- Unit cards (Bryan's design, after Dark Descent's style of HUD; our own look): float over the bottom of the map for the selected team(s), all four when both teams are selected. Each card: procedural portrait, callsign + name, status word, a visual-only heart monitor (no sound), the weapon (Bryan, like Dark Descent: our own silhouette drawing of the rifle (a shotgun one too, for later) with its name, `GUN_SVG`; picture only when four cards show) and equipment (C4 and grenade buttons with counts). Monitor colour: green ≥70 HP, yellow ≥35, orange below, red when downed (erratic, ~150 bpm), grey flatline when dead; rate ≈ 66 + suppression×55 + injury×0.45 + moving (sneak 8 / run 24) + contact 10. Tap a card to select just him; the cards on show stay as they were (`cardGroup` in state.js, kept by `select()` when one soldier is picked from the group already showing). Tap his card again to go back to the whole group on show (Bryan). Tabs, lasso, tapping a soldier on the map (his team) and Clear reset which cards show; Clear hides them. Bryan wants to test the portraits and judge them.
- One-finger drag on empty ground: pan the map (with glide). Drag starting on a soldier: draw his route. Pinch: zoom 1–4×. Two-finger twist: rotate the camera around the point between the fingers (starts after 0.2 rad of twist so pinches don't turn it; `yaw` in scene.js). Two fingers dragged together orbit the camera: pushing up tilts towards the horizon, pulling down tilts back (inverted on purpose, like Ashvale) (pitch down to 14°; `tilt`, `tiltCam`), left/right spins it round the view centre (`ORBIT_SPIN`), the scene following the fingers. The gesture decides orbit vs pinch/twist from each finger's own movement (both >8 px the same way = orbit; opposite ways or one finger alone = pinch), because touch events arrive one finger at a time. Fit map button resets zoom, rotation and tilt. Taps that don't land on the map (beyond its edge) are ignored.
- Tap a soldier: select his fire team. Hold a soldier (380 ms): select just him.
- Lasso select: hold empty ground (380 ms), then draw a loop round soldiers (freeform, closed automatically; `inLoop`). There is no Box button (Bryan).
- Tap a visible enemy: focus fire (before contact: open fire, which springs the ambush). Suppress button then tap an enemy: pin that area. Grenade: tap the grenade on a soldier's card (1 each, 170 range), tap again to cancel. Tap a downed teammate with a soldier selected: go revive.
- Keyboard: Space pause, Esc clear, 1/2 select teams, R sneak/run toggle, Q/E rotate camera 15°, wheel zoom, Shift+wheel tilt.

### Rules and numbers (first guesses, not tuned)
- Hit chance: 0.86 − dist/900; half cover −0.28, heavy −0.42; shooter moving −0.15, target moving −0.08; suppression up to −0.25; enemies −0.10. Clamped 5–95 %.
- Weapons: everyone carries an assault rifle for now (Bryan tried two shotguns, then took them out; `SHOTGUNNERS` is empty, the shotgun code and sound stay for later). Rifle: bursts of 3, every 1.6–2.2 s, range 380, damage 11–16 per hit (enemies ×0.6). Shotgun (dormant): one blast (4 pellet tracers) every 1.1–1.5 s, range 200 (`wRange`), hit chance 1 within 80 then −1/150 per unit beyond, cover counts less (−0.2 half / −0.3 heavy), damage 38–50 within 60 falling to 35 % at 260, +0.14 suppression per blast; recorded Benelli shotgun sound. Against an enemy in half cover: 6 m shotgun 80 % / rifle 51 %; 15 m shotgun 33 %; 25 m shotgun out of range, rifle 30 %. Enemies all carry rifles.
- Suppression: +0.06 per incoming shot, +0.17 per suppress-fire shot, decays 0.18/s. Pinned above 0.65: fires at 40 % rate, −0.25 accuracy, enemies stop repositioning.
- Cover = an object within 15 of the target that the shot line crosses. Full objects (containers, walls, truck, racks, fence) block line of sight; half cover (sandbags, crates, barrels, pallets, barrier, window sills) doesn't.
- Peeking round corners (both sides): if a full object within 22 blocks the line, a standing soldier can lean 8 or 14 sideways past its edge to see, shoot, suppress or throw (`leanPts`/`sightFrom` in map.js, `fireLine` in combat.js). After firing or throwing from a lean he stays leaned out 1.2 s (`PEEK_T`): enemies can see and shoot that spot, and he counts as half cover there. Moving cancels it. Cover scoring for moves counts a corner you can peek from as a spot that "sees" the enemy. UI: pill adds "· peek", shield turns amber, row reads Peeking.
- Downed players bleed out in 45 s; a teammate standing still within 24 revives in 3 s at 35 hp.
- Stealth (first pass, Bryan wants to discuss further): gait is automatic, sneak (24/s, low pose) while undetected with a live enemy within 300, run (54/s) otherwise (`gaitOf`). Unaware enemies build awareness 0..1 instead of spotting instantly (`sense` in combat.js): seen in the ±62° cone within 300 (or within 80 any direction at half rate) adds 1.6×(1−d/330)/s × running 1.3 / sneaking 0.6 / still in the open 0.45 / still in cover 0.3. Running within 110 is heard through walls (+0.5×(1−d/110)/s). Fades 0.15/s. At 0.35 he turns towards what he noticed ("?" callout); at 1 he raises the alarm for everyone. Gunfire and grenades still alert at once. Example spot times: 10 m in the open 2.1 s still / 1.6 s sneaking / 0.7 s running.
- Detection indicator top centre (`#alert`, `alertMeter` in hud.js): ring fills clockwise from the top with the most aware enemy, starting faint and see-through and getting more solid, redder, brighter and glowing as it fills; the filled arc throbs past 70 %, shows red "!!" once spotted. View cones redden with awareness.
- Enemies: cone vision (±62°, 300) until alerted, then reposition inside the warehouse when exposed, fall back below 40 hp.
- Counterattack (Bryan's second wave, now on foot since the jeep is out): when the warehouse is cleared, "All clear!" (grey-blue) fades in and out for 2.6 s; then a red 5 s countdown in hundredths with "INCOMING!" pulses where the detection ring sits; at zero "Enemy inbound!" and five hostiles (E6–E10, `wave:2`, `COUNTER`) come south over the main bridge and push (`assaultThink`: hold if they have a covered shot within 240, else move to a cover point within 130 that makes progress towards the nearest soldier, never within 70 of him, every 3–5 s). While counting down, previews judge cover against the bridge (`COUNTER_AT`). Clearing them shows "All clear!", then "Mission complete!" and the warehouse's report.
- Mission complete (Bryan's design): after wave two's "All clear!", "Mission complete!" (white with a gold glow), then the after-action report: one row per soldier with portrait, rank and level, stats (kills, best streak, revives, grenades, survived / downed / KIA) and an XP bar that fills (and flashes "Level up" / "Promoted"). XP: 40 per kill, 25 per kill beyond the first in the best streak (kills ≤8 s apart), 50 per revive, 15 per grenade, 60 for surviving; KIA soldiers earn nothing (lost). Level n→n+1 costs 100+15(n−1) XP. Ranks every 10 levels, Bryan's names: Private, Private First Class, Corporal, Sergeant, Gunnery Sergeant, Master Sergeant, First Sergeant, Master Gunnery Sergeant, First Major, Master Major, Commander (100+); I suggested an all-enlisted alternative (Staff Sgt, Sgt First Class, Master Sgt, First Sgt, Sergeant Major, Command Sergeant Major, Legend) and he hasn't picked yet. Level gives +0.2 % aim and −0.3 % suppression build-up per level (`rankAim`, `rankNerve`). Progress is saved in localStorage (`warehouseYard.squad.v1`); the intro card has a reset link. Failure still shows the old end screen, no XP.
- Temporary HQ points (Bryan: every captured objective becomes one): a medical box (heals 8 HP/s) and a supply box (after 4 s inside: the grenade and the demolition charge back), drawn as dashed boxes. The warehouse's (186,322 and 344,322, 90×70) come after its report with a popup (game paused until "Got it") and a short tour (`hqGotIt`/`TOURS`: the camera stops on each box, 3 s each, text in the `#tut` box); the tour's end starts objective 2. Later objectives add theirs when finished (`finishObjective`). No defence/raids at temporary HQs.
- Jeep (removed for now, Bryan: introduce it later): `vehicle.js` is still loaded but nothing spawns a jeep, so boarding, driving, the Dismount button and the gun-jeep wave are dormant. The design as it stood (4 seats, driver hidden, gunner on the MG, riders shoot, Dismount empties the jeep into cover, damage/smoke/fire/wreck, motor-pool repairs) is in git history before the mission rework.
- Objective 2, the bridge (`mission.js`, group 1): an MG gunner in a sandbag nest at the bridge's north end (`post`, machine-gun rules), a sentry in the pillbox (`booth`, elev 14, heavy cover) and three riflemen (`BR_ZONE`). All down: "Objective complete", boxes at the north end, save, then objective 3. The culvert and the rail bridge are the quiet and the exposed ways round.
- Objective 3, the fuel tanks (group 2): the container yard is held (Bryan: more units in the containers): nine men posted in its aisles and a two-man patrol walking them (east-west and north-south, 2.5 s pauses, until alerted; `route` handled in `missionTick`), all in `YARD2_ZONE`; then four depot guards (`DEP_ZONE`) and an RPG gunner (`RPG`: aims 1.3 s with an always-visible red reticle and "RPG!", a slow rocket lands 18–42 off; blast 40, 85 damage; reloads 8 s). Five tanks: shoot them (tap a tank with soldiers selected, ~25 per burst, `focusTank`) or use a demolition charge. A tank going up = big blast (140 damage, falling off over ~100, LOS) and chains to neighbours in ~0.5 s (they're close, so one usually takes them all), then burns. All gone: objective complete, boxes south of the depot, save.
- Demolition charges (Bryan: charges or gunfire): one per soldier (`u.charges`, C4 button with the count on his card left of the grenade; restocked at supply boxes). Tap C4, then a fuel tank or the server core: he walks up, plants for 3 s (yellow ring), the charge shows a countdown (8 s) and its blast radius, and he runs clear by himself to cover 13 m+ away (8 m for the core), out of the blast's sight if he can (`orderCharge`, `chargeTick`). Ordering him elsewhere while planting cancels it.
- Objective 4, the data center (group 3; Bryan: go inside): a building (`DC`, x 30–460, y −620 to −430; no roof, like the warehouse) with three ways in (front doors x 220–270, a west door into the office, an east door into the lobby), a lobby with a reception desk, an office with desks, and the server room with racks and the glowing server core (`CORE`). Outside, a container wall across the approach (y −390) with two openings, each covered by an MG nest just behind it, three riflemen (`DC_OUT`), a burnt-out car, barriers, razor wire and floodlights; five more inside (`DC_IN`). Blow the core with a charge, then send a soldier to the drawbridge's control panel (before that it says "Turn on the power to access drawbridge controls"): the drawbridge comes down over 3 s (`setBridge`), boxes by the panel, save, then the mission report ("Bridge, fuel depot and data center taken, drawbridge down"). Objective 5 shows as "coming next".
- The fortress (objective 5, to come): a giant ring (`FORT` centre (850,−1000), wall radius 380, mostly beyond the map) behind a bottomless moat to radius 440 (ground alpha hole `acan`, dark walls into fog; `pit` and `fortwall` disc objects), a gatehouse between two great towers with searchlights, the drawbridge between two lifting pylons, the control panel right of it (`PANEL`, `tapPanel`).
- Objective tracker (`#obj`, top left): "Objective n/5" and the current one; tap it for the whole list with the finished ones struck through (`updateObjUI`). The hint line says where to go next (`OBJ_HINT`).
- Saving (Bryan's design, `save.js`, localStorage `warehouseYard.save.v2`; older saves are ignored): automatic saves at four milestones: warehouse taken (`startHQ`), bridge taken, fuel depot destroyed, drawbridge down; a green "Saved · …" chip flashes top left (below the objective tracker). Stored: milestone, each soldier's HP, grenade and charge, and whether he's dead. The dead stay dead unless you start a New game; wounds are kept; a soldier down at the moment of saving is stored at 5 HP. Continue rebuilds the milestone directly (earlier objectives' boxes, burnt tanks, the destroyed core and lowered bridge as they were; the current objective's defenders spawn fresh; the lost are `gone`). New game clears the save; XP and ranks (progress.js) are kept either way.
- Pathfinding: A* on a 10-unit grid with string-pulling (cell rows start at `TOP`; iteration cap 40000 for the 100x166 grid). Cover points are generated around every object edge (merged if closer than 6).
- Spacing between soldiers' destinations: 20 in the open (`SPACE_OPEN`), 10 when both are at cover points (`SPACE_COVER`), so two can share a short bit of cover like the single sandbags. A crowded soldier's HP bar is lifted so the two don't overlap.

### Testing note
Headless browsers here have no GPU, so WebGL runs in software at ~3 fps: fine for screenshots and checking layout, useless for judging pacing. For local tests without network, install `three@0.128.0` from npm and serve `build/three.min.js` for the CDN URL (e.g. Playwright `page.route`), or swap the CDN tag for a local copy. Because the game state is global, tests can drive it straight from `page.evaluate` (`update(1/60)`, `tap(...)`, `units`), and seeding `Math.random` makes runs repeatable.
